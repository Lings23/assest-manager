# 新平台权限矩阵（阶段二基线）

## 适用范围

本矩阵约束 `platform/` 新平台。后端 IAM 授权上下文是安全边界；Vue 隐藏按钮只改善使用体验，不能代替服务端校验。

角色：

- `reporter`：填报和维护数据范围内的资产。
- `reviewer`：读取并维护数据范围内的资产，为阶段四审批角色预留。
- `auditor`：只读访问数据范围内的资产和版本。
- `admin`：平台管理和全量资产操作。

数据范围：

- `own`：本人创建的记录。
- `department`：当前部门记录。
- `descendants`：当前部门及所有下级部门记录。
- `global`：全部记录。

## 业务权限

| 能力 | reporter | reviewer | auditor | admin |
|---|---|---|---|---|
| 查询列表、详情和版本 | 数据范围内 | 数据范围内 | 数据范围内 | 全部 |
| 新建资产 | 允许 | 允许 | 禁止 | 允许 |
| 更新资产 | 数据范围内 | 数据范围内 | 禁止 | 全部 |
| 软删除、恢复资产 | 禁止 | 禁止 | 禁止 | 允许 |
| 管理用户、角色和部门 | 禁止 | 禁止 | 禁止 | 允许 |

`created_by`、`department_id`、版本号和软删除状态只能由服务端写入。未知字段在生成 SQL 前被 Schema 校验拒绝。列表、详情、更新、删除、恢复和版本查询必须使用同一 IAM 数据范围。

## 会话与管理约束

- Access Token 使用 RS256，固定 15 分钟有效期，并校验 issuer、audience、算法、JTI 和用户权限版本。
- Refresh Token 仅通过 `HttpOnly` Cookie 传输，数据库只保存哈希；每次刷新均轮换，检测到旧令牌复用时撤销整个会话族。
- 用户禁用、权限变更和改密立即增加权限版本并撤销已有 Refresh Session；旧 Access Token 因实时用户状态/版本校验失效。
- 首次管理员和标记为 `must_change_password` 的用户只能访问认证接口，完成改密并重新登录后才能进入业务接口。
- 管理员不能禁用自己或移除自己的管理员角色，避免当前管理会话自锁。

## 一致性验收

- 四类角色和四种数据范围必须有服务层自动化测试。
- 禁用、权限变更、注销、Refresh Token 轮换及复用检测必须有安全回归测试。
- 任一业务接口不得直接信任前端传入的用户、部门、角色或系统字段。
- 权限策略变更时先更新本矩阵及测试，再修改实现。
